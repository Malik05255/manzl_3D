# منزل H — Architecture

## الأساس

الصورة الأصلية ليست المشروع. بعد الرفع يتم إنشاء **Canonical FloorPlanModel** يحوي الجدران والغرف والفتحات والنصوص والمقياس والثقة. كل غرفة تحمل `boundaryWallIds` لربط فراغها صراحة بجدران النموذج بدل الاعتماد على مضلع بصري منفصل فقط. جميع التعديلات تحفظ كـRevisions من هذا النموذج.

```text
Web / PWA
   │
   ▼
Cloudflare Worker
   ├─ D1: metadata + revisions
   ├─ R2: source + canonical plan files
   └─ Queue
       │
       ▼
Managed Analyzer
   ├─ protected source pull
   ├─ PDF / image normalization
   ├─ Arabic + English OCR (Tesseract + optional Google Vision in parallel)
   ├─ walls + rooms
   ├─ metric calibration
   ├─ confidence validation
   └─ geometry-aware edit proposals
```

Analyzer يسحب المصدر من endpoint داخلي محمي بدل تمرير ملف كبير داخل Queue Worker، لتقليل ضغط الذاكرة وفصل التخزين عن الحوسبة.

## H Engineer

```text
Command
 → room resolution
 → metric constraints
 → adjacency search
 → candidate shared-wall moves
 → impact calculation
 → preview
 → server re-validation
 → user approval
 → revision
```

مثال: `عدل غرفة النوم إلى 5×5`. يولد المحرك بدائل حسب الغرف المجاورة واتجاه التوسعة. ويدعم قيودًا صريحة مثل `على حساب الصالة` أو `بدون تغيير الصالة` بحيث لا يعرض بدائل تخالف طلب المستخدم. عند الاعتماد يعيد الخادم حساب الاقتراح، ولا يثق عميًا ببيانات Preview القادمة من المتصفح.

الأوامر المفهومة حتميًا مثل تغيير المقاس أو دمج غرفتين لا تستدعي أي مزود لغوي خارجي؛ المزود الاختياري يستخدم فقط عندما تكون صياغة المستخدم غير واضحة للمحلل المحلي.

## قواعد الجودة

- لا يوجد تعديل بالمتر إذا لم يثبت المقياس.
- تعارض القراءات المترية يمنع المعايرة التلقائية بدل اختيار قيمة اعتباطية؛ القراءات ذات m/cm/mm الصريحة تفوق أرقام OCR غير المعلّمة.
- الاكتشاف منخفض الثقة لا يتحول إلى عنصر مؤكد.
- `confidence` تبقى درجة الاستخراج الآلي الأصلية، بينما `reviewed` يسجل مراجعة المستخدم و`provenance` يسجل مصدر العنصر مثل OpenCV أو OCR محلي أو `cloud-ocr` أو PDF native أو manual/AI.
- OCR السحابي اختياري ويعمل داخل الـAnalyzer فقط؛ المفتاح لا يمر إلى الـPWA. النتائج تدمج مع OCR المحلي حسب الموقع والنص والثقة، وتبقى طبقة نص PDF الأصلية ذات الأولوية عندما تكون متاحة.
- لا نخترع بابًا أو نافذة عند عدم كفاية الدليل.
- الجدار المضيف للفتحة المكتشفة يُطبع canonical كعنصر مستمر عبر فتحة الباب/النافذة؛ `Opening.wallId` لا يشير إلى نصف جدار مؤقت ناتج من الاستخراج.
- كل اعتماد ينتج Revision جديدة.
- بيانات الطابق (الاسم والمنسوب والارتفاع) تحفظ داخل Snapshot الـRevision أيضًا، لذلك الاستعادة تعيد حالة الطابق وليس الرسم وحده.
- لا يعتمد Manual Save أو H Engineer أي تغيير يضيف مشكلة حرجة جديدة مقارنة بالحالة المرجعية؛ نتيجة الفحص تُعاد للواجهة وتُحدد الغرف المتأثرة بصريًا.
- Validator يفحص room self-intersection وتداخل المضلعات غير المستطيلة، إضافة إلى اتصال الفتحات والجدران والأبعاد والمساحات.
- الحفظ يستخدم optimistic revision checks وفهرسًا فريدًا لمنع تبادل الكتابة بين تبويبين أو جهازين على نفس المشروع.
- المصدر الأصلي منفصل عن النموذج الهندسي.
- Queue التحليل source-aware: كل Job يحمل sourceKey وexpectedRevision، ويُفحص قبل بدء التحليل وقبل الحفظ حتى لا تكتب نتيجة قديمة فوق مصدر أو Revision أحدث.
- callbacks الداخلية للتقدم والمعاينة تتطلب نفس `sourceKey + revision` وتكتب إلى D1 بشرط ذري؛ معاينة R2 تستخدم مفتاحًا فريدًا ثم لا تُربط بالمشروع إلا إذا بقيت هوية Job الحالية مطابقة.
- ملفات PDF متعددة الصفحات تحفظ `page` و`pageCount` داخل Source metadata، ويمكن إعادة تحليل صفحة أخرى كـRevision جديدة دون استبدال التاريخ.
- CORS يفشل بأمان: نفس الأصل افتراضيًا، وأي واجهة منفصلة يجب تحديدها صراحة عبر `ALLOWED_ORIGIN`.
- المسودات التلقائية تحفظ في `draft_key` منفصل عن `plan_key` الخاص بآخر Revision؛ الرجوع عن التعديلات لا يعيد مسودة قديمة عند فتح المشروع لاحقًا.
- عمليات التحرير المتغيرة للحالة لا تكتب أثناء `queued/analyzing`، لمنع تبويب آخر من تحويل حالة المشروع إلى ready أو حفظ Revision أثناء إعادة التحليل.
- فهم اللغة يمكن تطويره بمزود AI لاحقًا، لكن القيود الهندسية تبقى مستقلة.
- OCR للأبعاد الرأسية يعمل بتمريرات 90° وإعادة إسقاط الإحداثيات، ومعايرة المقياس تدعم m/cm/mm ومقابلاتها العربية عند وجود الوحدة صراحة.

- بعد استخراج الغرف يعاد ربطها بالجدران هندسيًا، وتُرفض أي `boundaryWallIds` تشير إلى جدار غير موجود.

- الجدار الذي يرتبط بغرفة واحدة ويقع على الغلاف الخارجي للفراغات يُصنف مبدئيًا `exterior` ويُقفل تلقائيًا؛ الجدار المشترك بين غرفتين أو أكثر يصنف `interior`.

- تصنيف `structural` لا يُستنتج من الصورة وحدها؛ يحدده المستخدم، وعند اختياره يصبح الجدار محميًا.

- حماية الجدار enforced في الواجهة وH Engineer وAPI Save؛ لا يسمح بتغيير هندسته أو فتحاته وهو ما زال محميًا.

- `provenance` يتغير إلى `mixed` عندما يعدّل المستخدم أو H Engineer هندسة مستخرجة، بينما تبقى `confidence` الأصلية كما هي.

## المستقبل

الإنشاء من الصفر و3D سيستهلكان نفس FloorPlanModel. Renderer ثلاثي الأبعاد سيحوّل عناصر 2D نفسها إلى Meshes؛ لذلك لا يلزم هدم الأساس عند إضافة التجول الواقعي.
